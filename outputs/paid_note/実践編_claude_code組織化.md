## 第1章：この実践編で手に入るもの

前編を読んでいなくても、この章だけで全体像が分かるように先に要約しておく。

前編で話したのは、X・無料note・有料noteという3ステップの動線と、
その動線を「Xバズポスト作成部隊」「X交流部隊」「無料note作成部隊」「有料note作成部隊」
という4つの部隊に分けて運用する、という構造の話だった。

構造自体は理解できても、実際に手を動かす段階で多くの人が止まる。
理由は単純で、「具体的に何をどのファイルに、どう書けばいいか」が分からないからである。

この実践編で渡すのは、その「具体的に書く部分」そのものである。

- そのままコピーして使える `CLAUDE.md` の完成形テンプレート
- 4部隊（buzz_post / engagement / free_note / paid_note）の定義ファイルの実物
- 初日に何をどの順番で渡すか、という実際のコマンドと指示文
- 1週間運用したときに出てくるズレと、その直し方

これらは全て、テキストエディタにそのまま貼り付けて使える形で提供する。
読みながら理解する箇所と、コピーしてそのまま使う箇所を分けているので、
「読んだ後に何をすればいいか分からない」という状態にはならない。

この実践編の範囲は、「分かった」で終わらせることではない。
読み終えた直後に、1つの部隊だけでも実際に動かしてみるところまでを範囲としている。
完璧なセットアップを最初から目指す必要はない。
まず1部隊が動く状態を作り、そこから精度を上げていく順番で進める。

**前編未読でも進められる理由**
この実践編は、前編を読んでいない人でも進められるように作っている。
構造の話（なぜ動線が必要か、なぜ1人ではなく部隊に分けるのか）を理解していなくても、
ファイルをコピーして動かすことは可能である。
ただし、構造の理解なしに進めると、修正指示を出す段階で「何を直せばいいか」の判断基準がぶれる。
そのため、各章では実物の前に、関連する構造の要点を短く挟んでいる。

**この実践編で「やらないこと」**
誤解を避けるために、この実践編がやらないことも明記しておく。
バズるための投稿文の書き方そのものは教えない。
note自体の書き方講座でもない。
教えるのは「Claude Codeに役割を持たせて、出力を継続させる仕組みの作り方」だけである。
投稿やnoteの中身の質は、渡す素材とCLAUDE.mdの精度に依存する。
仕組みを作ることと、コンテンツの質を上げることは別の課題であり、
この実践編は前者だけを範囲にしている。

次の章から、実際に使うファイルの内容に入る。

## 第2章：CLAUDE.mdの実物テンプレート

CLAUDE.mdは、組織全体の方針を定義するファイルである。
Claude Codeはこのファイルを読み込んで、自分がどんな組織の一員として動くべきかを理解する。
ここが粗いと、4部隊全体の出力が粗くなる。逆に言えば、ここだけ丁寧に作れば、
他のファイルの精度は後から追いつく。

書く項目は5つに絞っている。多すぎると更新が止まるので、最初はこれで十分である。

**1. この組織の目的**
1行で書く。例：「Xへの投稿、無料noteの更新、有料noteの販売導線を、人手をかけずに回し続けること」。
動線（X→無料note→有料note）も併記しておくと、各部隊が自分の役割を動線の中で理解しやすくなる。

**2. 発信者のキャラクター設定**
トーン（誇張しない／断定しすぎない、など）、視点（ノウハウではなく構造を語る、など）、
一人称と文体（「僕」、短文・断定形、など）を3〜4行で書く。
ここが曖昧だと、部隊ごとに口調がバラつく。

**3. 各部隊の概要と役割**
表形式で「部隊名・役割・定義ファイル名」を並べる。これは後述の表をそのままコピーすればよい。

**4. 出力時の禁止事項（全部隊共通）**
「誇張表現を使わない」「売り込み口調にしない」「再現性を断言しない」など、
ジャンルを問わず守るべき項目をここに書く。ジャンル固有の禁止事項（薬機法・景表法など）は
各部隊ファイル側に書く。

**5. 文章スタイルの定義**
一文の長さ、比喩の使用可否、見出し・箇条書きの使用方針など、出力の見た目を決める項目。

これら5項目を埋めたものが、本リポジトリの `CLAUDE.md` である。
自分のジャンルに合わせて書き換える箇所は、1の「目的」と2の「キャラクター設定」だけで、
3〜5はそのまま流用できることが多い。

**書き換えチェックリスト**
コピーした後、最初に確認すべき項目を順番に並べておく。

1. 「目的」に書いた動線（X→無料note→有料note）は、自分の発信形態と一致しているか
2. 「キャラクター設定」の一人称・文体は、自分が実際に使っている口調と一致しているか
3. 「各部隊の概要」の表は、4部隊の名前と役割を自分のフォルダ構成と一致させているか
4. 「禁止事項」に、自分のジャンル特有の規制（薬機法・景表法・金融商品取引法など）が
   含まれているか
5. 「文章スタイル」は、実際に自分が書く文章の長さ・口調感と大きくズレていないか

この5項目を埋めた状態で1回動かしてみて、出力が想定と違う場合は、
どの項目が原因かをこのチェックリストの順番で確認すると、修正箇所を特定しやすい。
「全体的に違う」という感覚で終わらせず、5項目のどこがズレているかまで分解するのが、
CLAUDE.mdの精度を上げる最短ルートである。

## 第3章：4部隊の定義ファイル（コピー用）

各部隊のファイルは「役割」「出力形式」「禁止事項」の3項目だけで構成する。
これ以上書こうとすると更新が止まるので、最初はこの3項目に絞るのが正しい。

**buzz_post.md（Xバズポスト作成部隊）**
役割：Xに投稿するバズ投稿と記事投稿を作成する。
出力形式：バズ投稿は140字以内・1投稿、記事投稿は140字以内・無料noteへの誘導リンク付き・1投稿。
禁止事項：誇張表現、売り込み口調、抽象的な表現を使わない。

**engagement.md（X交流部隊）**
役割：フォロワーへのリプ、いいね対象アカウントの選定、引用ポストの作成。
出力形式：リプ案3パターン、引用ポスト案2パターン、いいね対象アカウント5件。
禁止事項：馴れ馴れしい口調、中身のない相槌リプを作らない。

**free_note.md（無料note作成部隊）**
役割：教育・信頼構築を目的とした無料noteの構成・本文作成。
出力形式：タイトル案3パターン、目次7章構成、各章1,500字前後。
禁止事項：売り込み口調、抽象的な結論、感情的なまとめを使わない。

**paid_note.md（有料note作成部隊）**
役割：収益化を目的とした有料noteの構成・本文・販売ページ作成。
出力形式：キャッチコピー3案、目次7章構成、各章2,000字前後、価格帯3パターン。
禁止事項：誇張表現、再現性の断言、景品表示法に抵触する表現を使わない。

ジャンルによって禁止事項に追加すべき項目が変わる。
例えば金融系の発信であれば景品表示法・金融商品取引法に関する表現の制約を、
健康・美容系であれば薬機法に関する制約を、各部隊ファイルの禁止事項に追記する。
この追記は最初から完璧でなくてよい。出力を見て、抵触しそうな表現が出た時点で追記すればよい。

4ファイルとも、本リポジトリの `agents/` フォルダにそのまま置いてあるので、
自分の作業フォルダにコピーするだけで使い始められる。

**部隊間の依存関係**
4部隊は独立しているわけではなく、出力の受け渡し関係がある。

- buzz_postの記事投稿は、free_noteが作る無料noteへのリンクを前提にしている
- free_noteは、paid_noteが作る有料noteへの導線を文中に設置する前提で書く
- paid_noteは、free_noteで構築した信頼の文脈を引き継いで書く

この依存関係があるため、4部隊を完全に独立して並行運用すると、
リンク先がまだ存在しない投稿や、文脈が繋がらないnoteが生まれることがある。
第4章で触れる「1部隊ずつ増やす」進め方は、この依存関係を崩さないための手順でもある。

## 第4章：素材の渡し方・初日の動かし方

ファイルが揃ったら、初日にやることは1つだけである。
4部隊を全部同時に動かそうとせず、buzz_post部隊1つだけを動かす。

**materials/に入れるもの**
最初の1回は、以下のどれか1つで十分である。

- 最近読んだ記事や見た動画の要点メモ（テキストファイル）
- 自分が普段話しているテーマについての箇条書きメモ
- 過去に反応がよかった投稿のスクリーンショットや本文コピー

完璧な素材を用意する必要はない。箇条書き5〜10行程度で十分に機能する。

**buzz_post部隊への指示**
作業フォルダで以下のように、定義ファイルと素材ファイルをまとめて渡す。

```
@agents/buzz_post.md @materials/今日の素材.txt
この素材を元に、バズ投稿1本と記事投稿1本を作って。
```

これだけで、140字以内のバズ投稿案と、無料noteへの誘導リンク付きの記事投稿案が出てくる。

**出力の保存先**
出てきた出力は `outputs/buzz_post/` に日付ごとのファイルとして保存する。
保存しておくことで、後から「どの素材からどの投稿が生まれたか」を振り返ることができ、
CLAUDE.mdや定義ファイルの修正に活かせる。

**2日目以降**
1つの部隊が問題なく動くことを確認してから、engagement部隊、
free_note部隊、paid_note部隊と1つずつ増やしていく。
4部隊を最初から並行で動かす必要はない。順番に増やす方が、
どこに問題があるかを特定しやすい。

**増やす順番の根拠**
順番はbuzz_post→engagement→free_note→paid_noteが基本である。
理由は、第3章で触れた依存関係の上流から順に固めていくためである。
buzz_postの出力が安定する前にfree_noteを動かしても、
記事投稿からの導線先がまだ整っていないため、確認すべきポイントが増えすぎてしまう。
1つずつ増やすことで、新たに発生した問題が「今追加した部隊由来」だと特定できる。

**4部隊が揃った後の運用**
4部隊が揃ったら、`claude-company --agents agents/` のようなコマンドで並列起動し、
朝に素材を渡して、出力を確認・修正指示するというルーティンに入る。
このルーティンの詳細（チェック項目・修正指示の出し方）は次の第5章で扱う。

## 第5章：出力チェックと修正指示の実例

出力が出たら、確認するのは3点だけである。文章の細部を全部読む必要はない。

**1. 方向性のズレがないか**
役割定義から外れていないかを確認する。

NG例：buzz_post部隊が、140字のバズ投稿のはずなのに長文の解説文を出してきた。
OK例：140字以内で、素材の要点が1つに絞られている。

**2. 禁止事項に抵触していないか**
誇張表現、売り込み口調、抽象的な結論が混ざっていないかを確認する。

NG例（free_note）：「これをやれば誰でも稼げます」→再現性の断言かつ誇張表現。
OK例：「条件が揃えば、収益は安定しやすくなります」→断定を避けた表現。

**3. 素材の内容を歪めていないか**
元の素材にない情報を勝手に追加していないかを確認する。

NG例：素材には書いていない具体的な金額や実績を、部隊側が勝手に補完している。
OK例：素材に書かれている情報の範囲内で、表現だけを整えている。

**修正指示の出し方**
修正箇所と理由を1〜2行で伝えるだけでよい。長い指示文は不要である。

```
バズ投稿の方が140字を超えている。140字以内に削って。
free_noteの第3章の結論が「誰でも稼げる」になっている。
「条件が揃えば」という表現に置き換えて。
```

このように、「どこが」「どう直すべきか」の2点だけを伝えると、
部隊側は迷わず修正して再出力する。指示が抽象的だと、出力も抽象的なまま返ってくる。

**確認にかける時間の目安**
1部隊あたりの確認は1〜2分で終わる範囲に収める。
3点チェックのどれにも引っかからなければそのまま採用し、
1点でも引っかかったら上記の形式で1行の修正指示を出す。
1つの出力に5分以上かけて読み込んでいる場合、チェック項目が多すぎるか、
定義ファイル側の禁止事項が足りていない可能性が高い。
その場合は出力を直すのではなく、定義ファイル側を直す方を優先する。
同じ修正指示を2回以上出している場合は、間違いなく定義ファイル側の問題である。

## 第6章：1週間運用したときに起きる典型的なズレと直し方

ファイルを揃えて動かし始めても、1週間ほど運用すると同じようなズレが出てくる。
ここでは典型的な3つのズレと、その直し方を取り上げる。

**ズレ1：バズ投稿と記事投稿の役割が混ざってくる**
バズ投稿のはずなのに無料noteへの誘導リンクが入ってきたり、
記事投稿のはずなのに誘導リンクがなかったりする状態。

直し方：`agents/buzz_post.md` の出力形式に、
「バズ投稿にはリンクを入れない／記事投稿には必ずリンクを入れる」と明記し直す。
最初の定義ファイルでは暗黙の前提になっていた部分を、明文化する。

**ズレ2：無料noteの導線が売り込みっぽくなってくる**
有料noteへのリンクを置く位置や言い回しが、回を重ねるごとに強くなっていく状態。

直し方：`agents/free_note.md` の禁止事項に、
「有料noteへのリンクは『補足資料として』という文脈以外で置かない」と具体的に追記する。
「売り込み口調にしない」だけでは抽象的すぎて、部隊側の判断がブレる。

**ズレ3：有料noteの再現性表現が強くなりすぎる**
販売ページのキャッチコピーが回を重ねるごとに「絶対」「誰でも」に近づいていく状態。

直し方：`CLAUDE.md` と `agents/paid_note.md` の禁止事項に、
NGワードを具体的にリストアップする（「絶対」「誰でも」「必ず」など）。
抽象的な禁止事項を、出力で実際に出てきた表現をもとに具体化していくのが正しい順番である。

3つとも共通しているのは、「最初の定義ファイルが抽象的だった部分」が、
運用を重ねるうちに表面化するという点である。
これはファイルの作り方が悪かったわけではなく、運用しながら精度を上げる過程として正常である。

**ズレに気づくタイミング**
多くの場合、ズレは出力1つを見ても気づきにくい。
過去3〜5回分の出力を並べて見比べたときに、「だんだん強くなっている」と気づく形で発覚する。
そのため、`outputs/` に出力を保存しておく運用には、振り返りのための意味もある。
週次の振り返り（前編で触れた週1回の作業）の際に、直近1週間分の出力をまとめて見直し、
表現が強くなっていないかを確認する習慣をつけておくと、ズレを早期に発見できる。

**直してもズレが再発する場合**
同じ修正を2〜3回繰り返しても改善しない場合、原因は禁止事項の書き方ではなく、
渡している素材自体に強い表現が含まれている可能性がある。
その場合は部隊側のファイルではなく、`materials/` に入れる素材を見直す。
仕組み側の問題か、素材側の問題かを分けて考えることが、無駄な修正を減らすコツである。

## 第7章：このまま使える次の一歩

ここまで読んで、ファイルの内容と動かし方は分かった状態になっているはずである。
最後に、読み終えた直後にやることを3つだけに絞って提示する。

**1. テンプレートを自分用の作業フォルダにコピーする**
`CLAUDE.md` と `agents/` 配下の4ファイル、`outputs/`・`materials/` のフォルダ構成を、
自分の作業フォルダにそのままコピーする。`CLAUDE.md` の「目的」と「キャラクター設定」だけ、
自分のジャンルに合わせて書き換える。

**2. materials/に今日使う素材を1つだけ入れる**
完璧な素材集めをする必要はない。第4章で触れたとおり、箇条書き5〜10行で十分である。
「素材が完璧に揃ってから始める」と考えると、永遠に始まらない。

**3. buzz_post部隊だけを動かしてみる**
4部隊を同時に揃えようとせず、buzz_post部隊1つだけを動かす。
出力が出たら、第5章の3点チェックを実施し、必要であれば修正指示を出す。

この3つができれば、今日中に「投稿案が出てくる状態」を作ることができる。
そこから、engagement・free_note・paid_noteの順に部隊を増やしていけば、
前編で説明した4部隊体制に自然と近づいていく。

構造は前編で説明した。実物は今回渡した。
あとは、今日のうちにbuzz_post部隊を1回動かしてみることだけが残っている。
